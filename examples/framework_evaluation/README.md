# Framework Evaluation. Автоматический сбор реальных наблюдений для Agenomics

Автоматически прогоняет все обнаруженные фреймворки, строит честный
`AgentGenome` из захваченных логов и записывает реальный `TrustScorer`
результат в персистентный `EvidenceStore` (AEP-001).

## Быстрый старт

```bash
pip install agenomics
```

1. Скопируйте `frameworks/_example_template.py` в `frameworks/ваш_агент.py`
   (без ведущего подчёркивания), замените `run()` на реальный вызов
2. Запустите: `python run_all_frameworks.py`
3. Повторяйте, история накапливается в `frameworks_evidence.db`

## Что уже включено: 29 шаблонов-адаптеров

Наличие шаблона не означает гарантированную production-совместимость.
Это отправная точка для сбора реальных наблюдений, не готовая интеграция.
Синтаксис каждого шаблона сверен с актуальной документацией на момент
добавления, но библиотеки быстро меняются, а некоторые требуют внешних
сервисов или платных API-ключей, без которых прогон честно завершится
ошибкой (что тоже фиксируется как наблюдение, а не ломает весь процесс).

**Работают через простой `pip install` и не требуют внешнего сервера:**
LangChain, AG2 (AutoGen), CrewAI, LlamaIndex, Semantic Kernel, LangGraph,
Haystack, CAMEL-AI, OpenAI Agents SDK, Griptape, MetaGPT (платный API,
дорогой прогон), Agno, Pydantic AI, smolagents, DSPy, Microsoft Agent
Framework, Marvin, Atomic Agents, Praison AI, txtai, AgentScope.

**Требуют отдельно поднятого сервера или облачного аккаунта:**
Rasa (свой сервер), AutoGPT (Agent Protocol, свой сервер), Letta
(Letta Cloud или self-hosted Docker), Strands Agents (AWS Bedrock),
Google ADK (Google API-ключ), Portia AI (Portia Cloud или свои ключи).

**Не проверено до конца, честно помечено в коде:**
SuperAGI, неподдерживаемый проект с открытыми уязвимостями, шаблон
содержит `NotImplementedError` вместо выдуманного вызова API.

**Известные пересечения:**
txtai построен поверх smolagents (тот же движок, разный пакет и фокус).

## Автоматический запуск по расписанию

`.github/workflows/framework_eval.yml` прогоняет каждые 6 часов через
GitHub Actions. Важно: сам этот файл должен лежать в `.github/workflows/`
в корне репозитория, не внутри `examples/framework_evaluation/`, иначе
GitHub Actions его просто не увидит. Скрипты и БД при этом остаются в
`examples/framework_evaluation/`, это решается через `working-directory`
в самом workflow.

**Про кэш БД между запусками (`actions/cache`):**
- Кэш GitHub Actions иммутабелен: записанный под конкретным ключом кэш
  нельзя перезаписать в конце того же запуска. Поэтому используется
  уникальный ключ на каждый запуск (`github.run_id`) плюс `restore-keys`
  по префиксу, чтобы находить самый свежий предыдущий кэш при
  восстановлении.
- GitHub удаляет неиспользуемые кэши через 7 дней и держит лимит 10GB
  на репозиторий. При расписании раз в 6 часов это не проблема, кэш
  обновляется чаще, чем истекает. Если смените cron на реже раза в
  неделю, переключитесь на настоящую БД (Postgres/S3) вместо кэша.

Загрузите этот репозиторий (или папку) на GitHub, включите Actions,
дальше расписание работает само, без ручного запуска.

## Структура

- `capture_log_v2.py`: безопасный захват логов (падение одного
  фреймворка не мешает остальным)
- `genome_from_capture.py`: честное построение генома. `data_safety`
  через реальный детектор утечек секретов, `predictability` из истории
  3+ прогонов (реконструируется из `EvidenceStore`, переживает
  перезапуск процесса), `bias_control`/`transparency` осознанно `None`,
  их нельзя вывести из лога выполнения, `has_ledger` по умолчанию
  `False`, захват лога инструментом не делает агента обладателем
  собственного журнала решений
- `full_pipeline.py`: склеивает всё в один вызов
  `run_framework_and_record()`
- `run_all_frameworks.py`: авто-обнаружение плагинов в `frameworks/`
- `test_pipeline.py`: 12 тестов на всё вышеперечисленное

## Честная граница

`declared_score` в каждом наблюдении: это настоящий
`TrustScorer.score()`, а не заглушка, но построенный на частичном
геноме (2 из 5 осей выводятся автоматически, 2 остаются
недостаточными для оценки). Confidence в отчёте будет честно
невысоким, пока вы не дополните `bias_control`/`transparency` вручную
(например, через промпт Trust Auditor) для каждого фреймворка отдельно.
