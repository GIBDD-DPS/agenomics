# Security Policy

## Поддерживаемые версии

Agenomics следует semver 0.x, обратная совместимость между minor-версиями
не гарантируется до релиза 1.0.0. Патчи безопасности выпускаются только
для последней опубликованной версии на PyPI.

| Версия | Поддерживается |
|---|---|
| 0.7.x (последняя) | Да |
| < 0.7.0 | Нет |

## Как сообщить об уязвимости

Если вы нашли уязвимость в коде Agenomics (не в сторонних библиотеках,
которые Agenomics использует как зависимости), пожалуйста, сообщите
через GitHub Issues с пометкой `security`, либо напрямую автору:
dmitry@prizolov.ru.

Не публикуйте детали эксплуатации в открытом Issue до координированного
раскрытия. Если уязвимость подтвердится, исправление будет выпущено как
патч-релиз, и в CHANGELOG.md появится честное описание находки, по тому
же принципу, по которому в проекте документируются все остальные баги.

## Приватность данных в EvidenceStore

`agenomics.EvidenceStore` хранит наблюдения и инциденты локально, в
SQLite-файле на вашей машине или сервере. Agenomics не отправляет данные
никуда без вашего явного кода. `Incident.description` по протоколу
AEP-001 обязан быть коротким служебным резюме, не сырым пользовательским
текстом, подробнее см. `docs/AEP-001.md`, раздел Privacy.

## Секреты в примерах интеграции

Шаблоны в `examples/framework_evaluation/frameworks/` используют
переменные окружения (`GROQ_API_KEY`, `GOOGLE_API_KEY`, `HF_TOKEN`) для
ключей API. Никогда не коммитьте реальные ключи в репозиторий.
`genome_from_capture.py` включает детектор утечки секретов в захваченных
логах, но это эвристика, а не гарантия, и не заменяет собственную гигиену
работы с ключами.

## Известные ограничения (не уязвимости, но стоит знать)

- `agenomics.GenomeLedger`, локальный in-memory прототип, не защищён
  от подмены на уровне файла/процесса. Не полагайтесь на него как на
  криптографически надёжный аудит-лог в продакшене.
- Веб-API (`agenomics/api.py`) на момент версии 0.7.8 не имеет
  аутентификации или rate limiting. CORS настроен с v0.7.8, но открыт
  для всех origin (`allow_origins=["*"]`), это осознанный выбор для
  публичного unauthenticated API, а не остаточный пробел. Если добавите
  аутентификацию позже, сузьте `allow_origins` до конкретных доменов.
  Не разворачивайте API как публичный endpoint без дополнительного слоя
  защиты (обратный прокси, API gateway и т.д.).
