## Ключевая находка v0.1 → как она исправлена в v0.2

**Находка (v0.1)**: `DriftMonitor` (v1) не обнаруживал mild-деградацию
вовсе за 15 шагов — задокументировано как реальное ограничение, не
скрыто.

**Исправление (v0.2)**: `DriftMonitorV2` с rolling window + EWMA +
явной классификацией тяжести обнаруживает mild-деградацию за разумное
окно (см. `Drift Detection v2`). Найдена и исправлена *новая* проблема,
обнаруженная при калибровке v2: колебания (oscillation) без тренда
изначально ложно классифицировались как `sudden`; исправлено через
подсчёт смен знака приращений, отличающий колебание от единичного
устойчивого скачка. Честный остаточный дефект: первые ~2 снимка
колебательного паттерна (до заполнения rolling window) всё ещё могут
классифицироваться неточно — это transient, не устранённый полностью,
и заявлять обратное было бы нечестно.

## Evidence Quality (v0.6.1) — устойчивость метрик

Не новые метрики самой методологии, а проверка устойчивости уже
существующих результатов к малым изменениям параметров.

| Проверка | Результат |
|---|---|
| Weight Sensitivity (max |Δscore| при сдвиге веса на ±10%) | **7.1 баллов** |
| Threshold Sensitivity — ложные срабатывания на no_drift | **Нет** ни при одном из проверенных порогов |
| Threshold Sensitivity — mild_threshold=0.10 (слишком мягкий) | **mild-деградация не обнаружена вовсе** |
| Compatibility Accuracy v2 — Bootstrap 95% CI (1000 пересемплирований) | **[1.0000, 1.0000]** |

**Находка**: ось `accountability` на порядок чувствительнее остальных
(0.7 → 7.1 балла при росте сдвига веса от 1% до 10%), потому что она
взаимодействует с потолком автономности (`_AUTONOMY_TRUST_CAP`) — малый
сдвиг веса может протолкнуть агента через порог потолка. Остальные оси
меняются кратно медленнее. Это не дефект, а ожидаемое следствие того,
что `accountability` — единственная ось, завязанная на жёсткое правило
(cap), а не только на линейный вес — но это стоит иметь в виду тем, кто
настраивает `weight_profile` вручную.

**Честная оговорка про Bootstrap CI**: интервал `[1.0000, 1.0000]`
означает, что разделение классов в синтетическом наборе (270 случаев)
настолько чистое, что даже 1000 пересемплирований не находят ни одного
случая нарушения. Это говорит об устойчивости МЕТРИКИ на ЭТОМ наборе —
не о том, что реальная неопределённость методологии равна нулю.

## Как воспроизвести эти цифры

```bash
git clone https://github.com/GIBDD-DPS/agenomics.git
cd agenomics
pip install -r requirements.txt
PYTHONPATH=. python3 -m benchmark.run_benchmark
```

Все сценарии основного набора метрик детерминированы (без `random`).
Bootstrap CI в Evidence Quality использует `random` с фиксированным
seed (42) — тоже воспроизводимо, но по другому механизму. При том же
коде вы должны получить **ровно те же числа**, что в таблице выше.
Если нет — это регрессия, о которой стоит сообщить через GitHub Issues.

## Ограничения, которые остаются в силе

Compatibility Accuracy v2 (n=270) — по-прежнему **синтетический**
ground truth, сконструированный вручную, не выборка реальных
конфликтов агентов. 270 случаев ощутимо надёжнее 4, но это всё ещё не
замена реальным данным — см. `docs/SPECIFICATION.md`, раздел 10.
