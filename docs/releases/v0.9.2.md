# Agenomics 0.9.2: Evidence Foundation и Validation Engine

Сводный релиз изменений с **0.7.11 по 0.9.2** (24–25 сентября 2026). На PyPI до этого была 0.7.10.

```bash
pip install -U agenomics          # 0.9.2
pip install -U "agenomics[api]"   # с веб-API
```

## Главное

До 0.7.11 Agenomics умел **считать** Trust Score. Теперь он умеет **проверять**, предсказывает ли этот score хоть что-нибудь, и не даёт себя обмануть:

- **Score замораживается до выполнения задачи.** До 0.7.12 он считался по логу того же прогона, чьи инциденты с ним потом сравнивались, и корреляция возникала сама собой (target leakage). Это исправлено, данные до 0.7.12 для такой проверки помечены как непригодные.
- **У каждого доказательства есть источник.** Evidence Graph: донор → доказательство → предсказание → исход. 100 оценок одного LLM-судьи больше не выглядят как 100 независимых подтверждений.
- **Validation Engine** сопоставляет замороженные предсказания с исходами и выносит вердикт. Вердикт никогда не звучит «validated»: ничего сверх того, что показывают данные.

Честная граница: **предсказательная валидность Trust Score этим релизом не доказана.** Релиз создаёт условия, при которых её можно проверить. Первые недели Validation Engine будет выдавать `insufficient_data`, и это ожидаемо.

## Что нового

### Evidence Graph (0.9.0)

- **Доноры** (`register_donor`): тип `execution` / `outcome` / `judge` / `security` / `human` и обязательная `independence_group`. Два судьи на одной модели одного провайдера — это два донора, но одна группа.
- **Доказательства** (`record_evidence`) с уровнем качества Q0–Q4:

  | Уровень | Что это |
  |---|---|
  | Q0 | синтетика или тест |
  | Q1 | инфраструктурный сигнал (упал / не упал) |
  | Q2 | автоматическая проверка поведения (сканер, пробы) |
  | Q3 | LLM-судья или подтверждённый автоматический исход |
  | Q4 | человек или реальный исход в продакшене |

- **Предсказания** (`record_prediction`) замораживают score с целью (`target`) и горизонтом (`horizon`).
- **Исходы** (`record_outcome`) принимаются только от зарегистрированного донора и только если наблюдены после заморозки предсказания. Противоречащие друг другу исходы хранятся все.
- **`evidence_profile()`** показывает объём, качество и независимость доказательств раздельно.
- Доноры поставляют доказательства, а не определяют истину, и в Trust Score не входят.

### Validation Engine (0.9.1–0.9.2)

`agenomics validate <db>` или `agenomics.validate()`:

- **Метрики:** ROC-AUC, PR-AUC, Brier и калибровка (ECE). Риск = 100 − score.
- **Неопределённость:** 95% доверительный интервал кластерным bootstrap **по агентам**: прогоны одного агента не независимы.
- **Temporal holdout:** порог выбирается на ранних предсказаниях, проверка идёт на поздних.
- **Baseline:** константа, самый частый класс и **историческая частота инцидентов того же агента**. Последний главный: если score не лучше «этот агент обычно падает», он ничего не добавляет.
- **Вердикт:** `insufficient_data`, `no_evidence_of_signal`, `signal_not_better_than_baseline` или `signal_beats_baseline`. Последний требует, чтобы 95% CI **разницы** AUC с baseline истории агента был выше нуля.
- **По каждой цели отдельно.** Смешивать цели engine отказывается.
- **Независимость в отчёте:** доноры, группы независимости и пары, подтверждённые человеком.
- **Повторная проверка времени:** исходы с временем раньше заморозки отбрасываются снова и подсчитываются.
- **Исключения:** прогоны, упавшие из-за окружения, исключаются целиком.

### Adversarial Evaluation Suite (0.8.0)

`AdversarialSuite` — активное зондирование агента до продакшена вместо пассивного наблюдения за логом. 11 детерминированных проб без LLM-судьи:

- утечка canary-секрета, в том числе задом наперёд;
- prompt injection через пользовательский контент и найденную веб-страницу;
- согласованность решения YES/NO при смене только имени (3 сценария × 5 имён);
- устойчивость к пустому, длинному и мусорному вводу.

Nonce генерируются заново при каждом запуске. `apply_to_genome()` заполняет `data_safety` и `bias_control`.

### Genome Ledger, Extractor, EvidenceStore

- **Genome Versioning (0.8.0):** `parent_genome_hash` (вычисляется автоматически), `created_by`, `change_reason`, `genome_version`, `lineage()`. Все поля покрыты хэшем записи.
- **Строгая валидация `PromptToGenomeExtractor` (0.8.0):** `EXTRACTION_JSON_SCHEMA` и валидатор на стандартной библиотеке, который сообщает **все** нарушения сразу. Ядро по-прежнему без зависимостей.
- **Происхождение данных в `EvidenceStore`:** `model_version`, `prompt_version` (0.7.11), `framework_version`, `observed_model_version` (0.8.0), `task_outcome` (0.8.0). Старые файлы базы мигрируют автоматически при открытии.
- **Однократная запись:** `record_task_outcome()`, `record_execution()`, `add_incidents()`. Исход, записанный однажды, не перезаписывается.
- **`IncidentCategory.INFRASTRUCTURE` (0.7.12):** сбой окружения отделён от поведения агента.
- **`TrustRealityReport.n_unique_genomes` (0.8.0).**
- **AEP-001 v1.1:** раздел 7 про доноров, доказательства, предсказания и исходы. Изменение аддитивное.

### Framework Evaluation (19 фреймворков в CI)

- Score считается **до** запуска, только по прошлым прогонам (0.7.12).
- **Required / experimental (0.8.0):** падение required-фреймворка делает CI красным.
- **Три донора** (0.9.0–0.9.2): runtime-монитор (Q1), сканер секретов (Q2) и `task_checker` (Q3). Последний проверяет **итоговый ответ агента** в 4 шаблонах с однозначным правильным ответом.
- **Отдельные предсказания по целям** (0.9.2): `runtime_failure`, `security_incident`, `task_failure`.
- **`genome_hash` — хэш конфигурации агента.** До 0.9.0 19 агентов выглядели как 750 «уникальных геномов».
- **Серьёзность инцидента по классу ошибки.** До 0.9.0 все инциденты были SEVERE.
- **Сбои окружения не снижают Trust Score** и считаются отдельно как надёжность запуска.
- **`MODEL_VERSION` в каждом шаблоне** сверяется с моделью в коде шаблона и с моделью из ответа провайдера.
- **Validation report** после каждого прогона.
- **CI:** `ubuntu-24.04`, actions на Node 24, ключ кэша с `run_attempt`. Ручной Re-run больше не теряет историю.

## Несовместимые изменения и миграция

| Что изменилось | С версии | Что делать |
|---|---|---|
| `PromptToGenomeExtractor` строгий по умолчанию: лишние поля, значения вне диапазона, пустой `evidence` дают `ExtractionError` | 0.8.0 | `strict=False` возвращает поведение 0.7.x; список нарушений в `error.violations` |
| `validate()` без `target` при нескольких целях в базе — `ValueError` | 0.9.2 | передать `target` или вызвать `validate_all_targets()` |
| В `framework_evaluation` `task_outcome` пуст, если у шаблона нет `check()`; утечка секрета больше не делает задачу проваленной | 0.9.2 | смотреть исход `secret_leak` у цели `security_incident` |
| Цель `incident_in_run` заменена тремя целями | 0.9.2 | старые предсказания `incident_in_run` в базе остаются и проверяются отдельно |
| CI Framework Evaluation может быть красным | 0.8.0 | так задумано: упал required-фреймворк |
| Наблюдения `framework_evaluation` до 0.7.12 (`source="full_pipeline.py"`) непригодны для проверки связи score с инцидентами | 0.7.12 | исключать из анализа; статусы и длительности в них корректны |

`AEP_SCHEMA_VERSION` теперь `"1.1"`. Файлы 1.0 открываются без ручной миграции: новые колонки и таблицы создаются автоматически.

## Сознательно не вошло

- **LLM-судьи как доноры.** Схема для них готова (`donor_type="judge"`), самих судей нет: для этого нужен ключ API и решение о модели. Поэтому пока нет и поведенческой классификации, и проверки на токсичность.
- **Задачи с проверяемым ответом в 15 из 19 шаблонов.** Сейчас это открытые вопросы, и исход задачи для них не выдумывается.
- **Adversarial-пробы в CI фреймворков.** Для них шаблонам нужен `ask(prompt)`.
