## 0. Цель и границы

Цель: превратить цепочку «замороженное предсказание → исход →
доказательство → проверка» в систему, которая копит доказательства
воспроизводимо, отличает независимые доказательства от повторных и честно
сообщает, какие утверждения данные уже позволяют, а какие нет.

Не входит в релиз (без исключений):

- новые шаблоны фреймворков, кроме замены сломанных;
- изменения формулы Trust Score и осей генома;
- новые измерения оценки, dashboard, frontend, blockchain, эволюция;
- переписывание исторических данных (инциденты `other`, `severe`
  остаются как есть).

Правило совместимости: только добавление. Существующие колонки, таблицы,
методы и ключи JSON не удаляются и не меняют смысл. База 0.9.5
открывается кодом 0.9.6 без ручных действий, всё новое создаётся
миграцией.

| Bootstrap по агентам | `bootstrap_auc_ci(by_agent=True)` |

## 2. Схема базы

Файл: `agenomics/evidence_graph.py`. У графовых таблиц сейчас нет
миграции колонок (есть только у `observations`, `_EXPECTED_OBSERVATION_COLUMNS`
в `evidence.py`). Добавить `_EXPECTED_GRAPH_COLUMNS: Dict[str, Dict[str, str]]`
и в `_migrate_schema()` для каждой таблицы `ALTER TABLE … ADD COLUMN`
недостающих колонок, тем же способом.

### 2.1. `predictions`: снимок на момент заморозки

Новые колонки (все `TEXT`, допускают NULL для строк до 0.9.6):
`trust_model_version`, `genome_hash`, `genome_version`, `model_version`,
`prompt_version`, `framework_version`, `task_version`, `environment_id`,
`snapshot_json`.

- `record_prediction()` копирует эти поля из строки `observations`
  в момент заморозки; `task_version` и `environment_id` принимает
  аргументами (по умолчанию NULL). `snapshot_json` содержит все поля
  снимка плюс `trust_score` и `frozen_at` одним JSON с отсортированными
  ключами.
- Новая колонка `snapshot_sha256`: SHA-256 от `snapshot_json`.
  `verify_prediction_integrity()` пересчитывает хэш каждой строки и
  сверяет поля снимка с колонками.
- Уникальность: `CREATE UNIQUE INDEX IF NOT EXISTS ux_predictions_obs_target
  ON predictions(observation_id, target)`. Перед созданием миграция
  проверяет дубликаты; если они есть, индекс не создаётся, а
  `evidence_profile()` показывает их число (данных не удалять).

### 2.2. Неизменяемость (append-only)

В `GRAPH_SCHEMA_SQL`:

```sql
CREATE TRIGGER IF NOT EXISTS predictions_no_update BEFORE UPDATE ON predictions
BEGIN SELECT RAISE(ABORT, 'predictions are append-only'); END;
CREATE TRIGGER IF NOT EXISTS predictions_no_delete BEFORE DELETE ON predictions
BEGIN SELECT RAISE(ABORT, 'predictions are append-only'); END;
```

То же для `outcomes` и `evidence`. Исключение для миграции: заполнение
новых колонок старых строк (2.1, 2.4) выполняется до создания триггеров,
в одной транзакции. Будущие миграции, которым нужно заполнить колонки
старых строк, в одной транзакции удаляют триггеры, заполняют и создают
их заново; это единственный путь изменения, и он есть только в коде
миграции. Исправление ошибочной записи оформляется новой
строкой (для исхода: `details` со ссылкой `supersedes=<id>`), как в
`CREATION_RECORD.md`.

### 2.3. `outcomes`: класс, качество, происхождение

Новые колонки: `outcome_class TEXT`, `quality_level TEXT`,
`source_reference TEXT`, `collector_version TEXT`, `fingerprint TEXT`.

`outcome_class`, закрытый список (константа `OUTCOME_CLASSES`):

| Класс | Исходы | Смысл |
|---|---|---|
| `TASK` | `task_failure` | агент не выполнил задачу |
| `SECURITY` | `secret_leak` | утечка |
| `RUNTIME` | `execution_error` | агент упал не из-за окружения |
| `BEHAVIORAL` | исходы LLM-судьи (зарезервировано) | поведение |
| `INFRASTRUCTURE` | `infrastructure_error` | окружение, не агент |

Подтип окружения не вводится отдельным классом: он уже есть в классе
ошибки (`rate_limit`, `auth_error`, `provider_routing_error` — провайдер;
`import_error`, `known_upstream_bug` — зависимости). Для
`INFRASTRUCTURE` класс ошибки пишется в `details` как
`error_class=<класс>`.

- `record_outcome()` принимает `outcome_class`; если не передан, берёт
  из таблицы соответствия `OUTCOME_CLASS_BY_TYPE`; неизвестный тип без
  класса: `ValueError`.
- `quality_level` исхода: передаётся явно, по умолчанию берётся
  максимальный уровень доказательства того же донора по тому же
  наблюдению; если доказательства нет: `ValueError`. Это закрывает
  пункт плана «фильтр по quality_level: у исходов его нет».
- `collector_version`: `agenomics.__version__` при записи.
- Старые строки: миграция заполняет `outcome_class` по таблице
  соответствия (детерминированно, без догадок); `quality_level` по
  правилу выше; остальное NULL.

### 2.4. Дедупликация

`fingerprint = sha256("|".join([...]))`:

- у доказательства: `observation_id, donor_id, evidence_type, source_reference или ""`;
- у исхода: `prediction_id, donor_id, outcome_type, source_reference или ""`.

`CREATE UNIQUE INDEX … ON evidence(fingerprint) WHERE fingerprint IS NOT NULL`
(и для `outcomes`). `record_evidence()` и `record_outcome()` при
совпадении отпечатка не пишут вторую строку и возвращают id
существующей (идемпотентность). Миграция заполняет отпечатки старых
строк; строки-дубликаты получают NULL и считаются в
`evidence_profile().n_duplicates` (не удаляются).

## 3. Независимость

Файл: `agenomics/validation.py`.

В `ValidationReport` добавить:

- `outcomes_per_group: Dict[str, int]` — сколько пар цели опираются на
  исход каждой группы;
- `max_group_share: float` — доля крупнейшей группы;
- `independence_warning: Optional[str]` — текст, если групп меньше
  `PROTOCOL_THRESHOLDS["min_groups"]` или `max_group_share > 0.9`.

В `EvidenceProfile` добавить `evidence_per_group` (уже есть как
`independence_groups: Dict[str, int]`, переименование не делать, только
печатать в шапке) и `n_duplicates`.

Эффективную независимость не выражать одним «коэффициентом»: печатать
число групп, распределение по группам и предупреждение. Сводный индекс
без обоснованной формулы создаст ложную точность.

## 4. Q4: внешнее подтверждение исхода

Новый файл: `agenomics/external.py`.

```python
@dataclass(frozen=True)
class PredictionView:          # то, что видит верификатор: без trust_score
    prediction_id: int
    agent_id: str
    target: str
    horizon: str
    frozen_at: str
    task_version: Optional[str]
    environment_id: Optional[str]

@dataclass(frozen=True)
class ExternalVerification:
    occurred: bool
    outcome_type: str
    source_type: str           # "external_system", "human_review", ...
    source_reference: str      # id записи во внешней системе, обязательно
    verification_method: str   # "api_assertion", "manual_review", ...
    verified_at: datetime      # время подтверждения во внешней системе

class ExternalOutcomeVerifier(Protocol):
    donor_id: str              # донор типа "outcome", своя группа независимости
    def verify(self, prediction: PredictionView) -> Optional[ExternalVerification]: ...

def record_external_outcome(store, prediction_id: int, verifier: ExternalOutcomeVerifier) -> Optional[int]:
    ...
```

Правила `record_external_outcome()`:

1. Верификатор получает `PredictionView`: Trust Score ему не передаётся,
   чтобы подтверждение не могло от него зависеть.
2. `verified_at` строго позже `frozen_at`, иначе `ValueError`.
3. Группа независимости донора верификатора не совпадает с группами
   доноров, уже давших исходы этому предсказанию, иначе `ValueError`
   (внешнее подтверждение не может быть тем же источником).
4. Пишется исход с `verification="ground_truth"`, `quality_level="Q4"`,
   `source_reference`, `details` с `source_type` и `verification_method`.

**Первый реальный источник Q4 — решение автора, до реализации.** В
`framework_evaluation` его нет и быть не может: задачи синтетические,
их проверка `check()` — это Q3. Q4 требует исхода, который наступает в
реальном мире и фиксируется внешней системой. Кандидат: проект
`prizolov-sports-ai` (прогноз агента → результат матча из внешнего
источника). В релиз входит интерфейс, тестовый верификатор и
документация; счётчик Q4 остаётся 0, пока источник не подключён, и
отчёт это показывает. Подделывать Q4 из внутренних проверок запрещено.

## 5. Отчёт Validation Engine

### 5.1. Уровень утверждений вместо нового вердикта

Предложенный `VALIDATION_BLOCKED` не вводить как пятый вердикт. Вердикт
отвечает на статистический вопрос (есть ли сигнал на этих данных), и
при Q4 = 0 он всё равно осмыслен. Отдельно добавить **уровень
утверждений** по порогам протокола:

- `PROTOCOL_THRESHOLDS` в `validation.py` — единственный источник чисел
  из раздела 6 протокола: `min_test_pairs=30`, `min_class_count=5`,
  `preliminary_events=20`, `preliminary_agents=20`, `min_groups=2`,
  `external_requires_q4=True`;
- `ValidationReport.claim_level` ∈ `exploratory` / `diagnostic` /
  `preliminary` / `external`;
- `ValidationReport.claim_blockers: List[str]` — что мешает следующему
  уровню, например `"событий 4 < 20"`, `"Q4 = 0"`, `"групп независимости 1 < 2"`.

Уровень `preliminary` дополнительно требует, чтобы тот же вердикт
`signal_beats_baseline` был получен на предыдущей когорте
(`--trust-model-version` предыдущей версии); если её нет, блокер
`"нет повторения на другой когорте"`.

### 5.2. Bootstrap по конфигурациям

Добавить `bootstrap_auc_ci(by="agent"|"genome"|"observation")` (старый
параметр `by_agent` оставить как псевдоним). `HoldoutResult` получает
`roc_auc_ci_by_genome`. Отчёт печатает оба интервала.

### 5.3. Полный отчёт

`agenomics validate <db> --report validation_report.md` пишет Markdown:

1. Когорта: версии модели доверия, период (`min/max frozen_at` пар), фильтры.
2. Объём: предсказания, прогоны, агенты, конфигурации, дубликаты.
3. Доказательства: Q0–Q4, по группам независимости.
4. Целостность: исходов раньше заморозки, предсказаний с нарушенным
   снимком (`verify_prediction_integrity()`), изменённых строк
   (триггеры исключают, печатается 0).
5. По каждой цели: события, метрики, baseline (с пояснением про
   фреймворк), bootstrap по агентам и по конфигурациям, вердикт,
   уровень утверждений и блокеры, предупреждение о независимости.
6. Устаревшие цели отдельным разделом в конце.

`--json` содержит те же поля. Текстовый вывод без `--report` остаётся
как есть, плюс строки уровня утверждений.

## 13. Уточнения при реализации

Решения автора: источник Q4 — `prizolov-sports-ai`; цели scorecard и
пороги протокола утверждены как в разделах 5.1 и 6.

Отличия реализации от текста выше, найденные при сверке с кодом:

1. **Исход неизвестного типа и исход без доказательства не дают
   `ValueError`** (п. 2.3, тест 5). Это противоречило бы п. 0 (API только
   расширяется): `record_outcome()` вызывают существующие тесты и внешний
   код с произвольными типами. Такой исход получает пустой класс или
   качество и считается в профиле (`n_outcomes_without_class`).
   Неизвестное значение, переданное явно (`outcome_class="MISC"`,
   `quality_level="Q9"`), по-прежнему `ValueError`.
2. **Уникальность предсказания — `(observation_id, target, horizon)`**, а не
   `(observation_id, target)`: одна цель на разных горизонтах законна,
   это проверяет существующий тест.
3. **Доля крупнейшей группы** считается от всех связей «пара – группа»:
   при делении на число пар пара, подтверждённая двумя группами, давала
   обеим долю 100% и ложное предупреждение.
4. **Снимки старых предсказаний не заполняются задним числом**: снимок
   означает «на момент заморозки», а у строк до v0.9.6 этого момента уже
   не восстановить. Они считаются как «без снимка», не как нарушения.
